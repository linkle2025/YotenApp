# 3. 構造（Structure）

[02_要件.md](./02_要件.md) の機能とコンテンツを、利用者が迷わない形に組み立てます。

- **情報の構造**：情報をどう分類し、どの画面に置くか（サイトマップ、URL）
- **操作の構造**：利用者がどの順で画面をたどるか（ユーザーの流れ、操作のルール）

あわせて、権限とデータの形もここで決めます。

---

## 3.1 サイトの区分

サイトを、誰が見るかで4つの区域に分けます。

| 区域 | 対象 | ログイン | 検索エンジン | 主な内容 |
|---|---|---|---|---|
| 公開区域 | 誰でも | 不要 | 載せる | トップ、無料診断、十干・通変星の解説、読み物、規約 |
| 認証区域 | 未ログインの人 | 不要 | 載せない | ログイン、会員登録、パスワード再設定 |
| 会員区域 | 会員 | 必要 | 載せない | ホーム、命式作成、鑑定記録、鑑定表、マイページ |
| 管理区域 | 管理者 | 必要（管理者のみ） | 載せない | ユーザー管理、奇門遁甲、解釈ルール、利用状況 |

## 3.2 サイトマップと URL

`段階` は [01_戦略.md の 1.8](./01_戦略.md#18-リリースの段階案) のリリース段階です。

```
/                                トップ（段階1は簡易版、段階3で紹介ページに）
├─ /shindan                      無料診断の入力（段階3）
│   └─ /shindan/result           無料診断の結果（段階3）
├─ /jikkan                       十干の一覧
│   └─ /jikkan/[slug]            十干の解説（例：/jikkan/kinoe = 甲）
├─ /tsuhensei                    通変星の一覧
│   └─ /tsuhensei/[slug]         通変星の解説（例：/tsuhensei/hiken = 比肩）
├─ /learn                        読み物（段階3）
│   └─ /learn/[slug]             記事
├─ /terms                        利用規約
├─ /privacy                      プライバシーポリシー
│
├─ /login                        ログイン
├─ /signup                       会員登録
├─ /forgot-password              パスワード再設定の申し込み
├─ /reset-password               新しいパスワードの設定（メールのリンクから）
│
├─ /home                         ホーム（会員のダッシュボード）
├─ /readings                     鑑定記録の一覧
│   ├─ /readings/new             命式作成
│   └─ /readings/[id]            鑑定表
│       └─ /readings/[id]/print  印刷用（段階2）
├─ /me                           マイページ
│   ├─ /me/profile               プロフィール（本人の生年月日など）
│   ├─ /me/account               メールアドレス・パスワード・表示モード
│   └─ /me/delete                退会
│
└─ /admin                        管理のトップ
    ├─ /admin/users              ユーザー管理
    ├─ /admin/usage              判定の要点の生成状況
    ├─ /admin/kimon              奇門遁甲（時盤・日盤）
    │   └─ /admin/kimon/daily    1日分の時盤
    └─ /admin/rules              解釈ルール（段階1は内容の確認のみ、段階4で編集）
```

### URL の決まり

- 英小文字とハイフンだけを使う。十干・通変星の slug はローマ字にする（[付録A の A.13](./付録A_鑑定ロジック仕様.md#a13-十干通変星のマスタ) に一覧）。
- 鑑定記録の `[id]` は推測されにくい UUID にする（現行は連番）。
- 現行の URL（`/calculate`、`/history`、`/fortune/:id`、`/mypage`、`/stems`、`/stars`、`/kimon-tonkou`）は、新版の対応する URL へ転送する。会員は登録し直すので、主に十干・通変星のページのためです。

## 3.3 ナビゲーション

### 会員区域（ログイン後）

主要な行き先を4つに絞ります。スマートフォンでは画面下のタブ、パソコンでは画面上部に置きます。

| 順 | 項目 | 行き先 | 理由 |
|---|---|---|---|
| 1 | ホーム | `/home` | 本人の鑑定表と最近の記録への入口 |
| 2 | つくる | `/readings/new` | 最もよく使う操作 |
| 3 | 記録 | `/readings` | 過去の鑑定記録 |
| 4 | マイページ | `/me` | プロフィール・設定 |

- 十干・通変星の解説は、鑑定表の中から開く。ヘッダーのメニューにも置く（現行はヘッダーの最上位にあるが、会員の主な行き先ではない）。
- 管理者には、メニューに「管理」を追加する。

### 公開区域

ヘッダー：ロゴ（トップへ）、無料診断、十干・通変星、読み物、ログイン、会員登録。ログイン済みなら「ホームへ」。

## 3.4 ユーザーの流れ

### 流れ1：初めての会員が、自分の鑑定表を見る（段階1）

```
会員登録（メール・パスワード・表示名）
  → 確認メールのリンクを押す
  → プロフィール入力（生年月日・時刻・出生地・性別）※スキップ可
  → 本人の鑑定記録を自動作成
  → 鑑定表（本人）
  → 「判定の要点を生成」→ 文章が順に表示される
```

- 登録画面の入力は3項目だけにする。生年月日は登録の後に聞く。
- プロフィールをスキップした人には、ホームで入力を促す。

### 流れ2：会員が、他の人（社員・子ども・相談者）の命式を作る（段階1）

```
ホーム or 下のタブ「つくる」
  → 命式作成（氏名・生年月日・時刻・出生地・性別）
  → 鑑定表
  → （必要なら）お気に入りに登録
```

- 入力の途中でページを離れても、入力内容をブラウザに一時保存しておく。

### 流れ3：会員が、以前の記録を見返す（段階1）

```
下のタブ「記録」
  → 一覧（検索・お気に入りで絞り込み）
  → 鑑定表
```

### 流れ4：初訪問者が、無料診断から会員になる（段階3）

```
検索・SNS → トップ or 十干の解説ページ
  → 無料診断（生年月日、時刻は任意）
  → 結果（日干と性質、スキル表の一部）
  → 「続きを見る」→ 会員登録
  → 診断した内容がそのまま鑑定記録として保存され、鑑定表（全体）へ
```

- 無料診断の入力は、登録が終わるまでブラウザにだけ置く。サーバーには保存しない。

### 流れ5：パスワードを忘れた（段階1）

```
ログイン →「パスワードを忘れた場合」→ メールアドレス入力
  → 「メールを送りました」（登録の有無にかかわらず同じ表示）
  → メールのリンク → 新しいパスワード → ログイン済みでホームへ
```

### 流れ6：管理者が、鑑定事例をもとに解釈ルールを調整する（段階1はファイル、段階4は画面）

```
（段階1）skill_rules.toml を編集 → テスト → プッシュ → 自動デプロイ → 鑑定表で確認
（段階4）/admin/rules で編集 → 試算（指定した鑑定記録で点数の変化を見る）→ 公開
```

## 3.5 権限

### ロール

| ロール | 意味 | 現行との違い |
|---|---|---|
| 会員（general） | 一般の会員 | 同じ |
| 占者（fortuneteller） | 鑑定をする人 | 段階1では会員と同じ。段階4で専用機能（要確認） |
| 管理者（admin） | 陽てん塾の運営者 | 同じ |

ロールは Supabase の `profiles` テーブルに持ち、管理者だけが変更できます。

### 権限の表

| 操作 | 未ログイン | 会員・占者 | 管理者 |
|---|---|---|---|
| 公開ページ・十干・通変星を見る | ○ | ○ | ○ |
| 無料診断（段階3） | ○ | ○ | ○ |
| 命式を作る・自分の鑑定記録を見る・消す | — | ○ | ○ |
| 他人の鑑定記録を見る | — | — | —（管理者でも見ない。件数だけ） |
| 判定の要点を生成する | — | ○（1日の上限あり） | ○（上限あり。変更可） |
| 会員の一覧・ロール変更・停止・削除 | — | — | ○（自分自身は削除不可） |
| 奇門遁甲 | — | — | ○ |
| 解釈ルールの確認・編集 | — | — | ○ |

- 「他人の鑑定記録は管理者でも見ない」は案です。サポートのために見られる必要があるかは要確認です。
- 権限は、画面の表示だけでなく、データベースの RLS とサーバー処理の両方で確かめます。

## 3.6 システム構成

```
ブラウザ
  │  HTTPS
  ▼
Vercel（東京）
  ├─ Next.js の画面（公開ページは事前に生成し、会員ページはサーバーで組み立てる）
  ├─ サーバー処理（Server Actions / Route Handlers）
  │    ├─ 命式の計算（TypeScript に移植したロジック）
  │    ├─ 鑑定スキル表の計算・解釈ルールの適用
  │    └─ 判定の要点の生成（Gemini を呼び、文章を順に返す）
  │
  ├──────────▶ Supabase（東京）
  │              ├─ Auth（会員・ログイン・メール認証・パスワード再設定）
  │              └─ PostgreSQL（RLS で本人のデータだけ読み書き）
  │
  └──────────▶ Gemini API（有料枠）
```

### 決めておく方針

| 項目 | 方針 |
|---|---|
| 計算をどこで行うか | サーバー側で行う。ブラウザに計算ロジックは置かない（結果の改ざん防止と、ロジックの保護） |
| 計算結果の保存 | 命式（四柱・蔵干・通変星・五行・格局など）は保存する。鑑定スキル表は、解釈ルールを変えたら変わるので、表示のたびに計算する（現行と同じ） |
| 計算ロジックの置き場所 | 画面から独立したパッケージ（例：`packages/meishiki`）にまとめ、単体でテストする |
| 解釈ルール | 段階1はリポジトリ内のファイル。デプロイのたびに検査する |
| 固定データ | 節入り時刻・局数・凶格はリポジトリ内のファイル。十干・通変星はデータベース |
| 判定の要点の上限 | 1日の生成回数はデータベースで数える（現行と同じ。サーバーレスでも正しく数えられる） |

## 3.7 データの形（Supabase のテーブル案）

すべてのテーブルで RLS を有効にします。

> 実装：`supabase/migrations/`（2026-11-09）。この節との主な違いと補足は次のとおりです。詳しくは [supabase/README.md](../supabase/README.md)。
> - 会員が直接変えられる列を、列ごとの権限で絞っている（profiles は display_name・display_mode、readings は name・is_favorite だけ）
> - 鑑定記録の作成・計算結果、判定の要点の作成は、サーバー（service_role）だけが行う
> - 役割・利用状態の変更と会員一覧は、管理者だけが使える関数（admin_update_user・admin_list_users）で行う
> - 生年月日は 1901-01-06 以降（節入りデータの最初の節より後）に制限している

### profiles（会員のプロフィール）

`auth.users` と1対1。会員登録のときに自動で作ります。

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid | `auth.users.id` と同じ |
| display_name | text | 表示名 |
| role | text | general / fortuneteller / admin。既定 general |
| display_mode | text | business / parent。既定 business |
| status | text | active / suspended |
| self_reading_id | uuid | 本人の鑑定記録（readings.id）。プロフィール未入力なら空 |
| created_at, updated_at | timestamptz | |

本人の生年月日などは、`readings` の本人分（`is_self = true`）に持たせます。プロフィールと鑑定記録の二重管理（現行の課題）をなくすためです。

**RLS**：本人は自分の行を読めて、display_name と display_mode だけ変えられる。role と status は管理者だけが変えられる。

### readings（鑑定記録）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid | |
| owner_id | uuid | profiles.id。削除時は一緒に消える |
| is_self | boolean | 本人の記録か（1人1件まで） |
| name | text | 氏名（任意） |
| birth_date | date | 生年月日 |
| birth_time | time | 出生時刻（時間不明なら空） |
| hour_unknown | boolean | 時間不明 |
| birth_place | text | 出生地（都道府県コード） |
| gender | text | male / female |
| result | jsonb | 計算結果（四柱・蔵干・通変星・五行・身旺身弱・格局・干合・大運） |
| calc_version | text | 計算ロジックの版。ロジックを直したら再計算の対象を探せる |
| is_favorite | boolean | |
| created_at, updated_at | timestamptz | |

- 現行は四柱の各要素を36個の列に分けていましたが、新版は `result` にまとめます。検索に使う列（日干など）が必要なら、別に列を持ちます。
- インデックス：`(owner_id, created_at desc)`、`(owner_id, is_favorite)`。

**RLS**：本人（owner_id）だけが読み書きできる。

### insights（判定の要点）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid | |
| reading_id | uuid | readings.id。削除時は一緒に消える |
| input_hash | text | 入力・プロンプト版・モデル名のハッシュ。古い解説を見分ける |
| prompt_version, model_name | text | |
| context | jsonb | 本人コンテキスト（段階2） |
| content | jsonb | 生成した文章（要約・職種・能力・活かし方） |
| input_tokens, output_tokens | integer | |
| created_by | uuid | 生成した会員 |
| created_at | timestamptz | |

インデックス：`(reading_id, input_hash)`、`(created_by, created_at)`（1日の上限を数えるため）。

**RLS**：鑑定記録の持ち主だけが読める。書き込みはサーバー処理（service_role）だけ。

### stems・stars（十干・通変星のマスタ）

現行の項目を引き継ぎ、`slug` を加えます。誰でも読めて、管理者だけが書けます。

### 段階4以降で追加する候補

- `rule_sets`：解釈ルールの版と内容（画面編集にするとき）
- `clients`：占者の相談者（占者向け機能）
- `subscriptions`：課金

## 3.8 操作のルール

全画面で共通にする決まりです。

| 場面 | ルール |
|---|---|
| 読み込み中 | 画面の形を保った仮の表示（スケルトン）を出す。文字だけの「読み込み中...」は使わない |
| 時間のかかる処理 | 判定の要点のように数秒以上かかるものは、進み具合を見せ、可能なら書き上がった部分から表示する |
| 空の状態 | 理由と、次にすべき操作のボタンを出す（例：「まだ記録がありません」＋［命式をつくる］） |
| エラー | 利用者の言葉で、何が起きたかと、どうすればよいかを書く。再試行のボタンを付ける。技術的な詳細は記録にだけ残す |
| 入力の誤り | 項目のすぐ下に、直し方を書く。送信前に確かめられるものは、送信前に知らせる |
| 削除 | 一覧での削除は、その場で消して数秒間「元に戻す」を出す。アカウントや他人のデータに関わる削除は、画面内の確認パネルで、消えるものを具体的に示す |
| 成功の知らせ | 画面の隅に短く出して、自動で消す（トースト） |
| 画面内の詳細 | 十干・通変星の解説などは、スマートフォンでは下から出るパネル、パソコンでは横から出るパネルで開く。Esc キーと背景のタップで閉じる |
| 入力の保持 | 命式作成の途中で離れても、入力はブラウザに一時保存する |
| ログインの期限切れ | 操作中に期限が切れたら、入力を失わずにログインし直せるようにする |
