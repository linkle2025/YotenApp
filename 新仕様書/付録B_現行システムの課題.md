# 付録B 現行システムの課題

今のアプリ（2026-11-09 時点）の不具合、使いにくい点、ドキュメントとのずれの一覧です。新版で必ず解消します。

- 「実測」は、実際に計算や API を動かして再現を確かめたものです。
- 「新版での対応」の段階は、[01_戦略.md の 1.8](./01_戦略.md#18-リリースの段階案) のリリース段階です。

---

## B.1 鑑定結果に関わる不具合（最優先）

| # | 内容 | 影響 | 確認 | 新版での対応 |
|---|---|---|---|---|
| 1 | **1月1日〜小寒前の月柱が誤る**。前年1月の丑月を拾う | 毎年1月初めの約5日間に生まれた人の月柱・格局・五行・スキル表・大運が誤る | 実測：1990-01-03 → 乙丑（正しくは丙子） | 段階1で修正。正解データで確認 |
| 2 | **時間不明でも0時として時刻を補正し、日柱が前日にずれる** | 時間不明で、補正が負になる地域・月の人の日柱（＝日干）が誤る。日干は鑑定の起点なので影響が大きい | 実測：1990-03-10 大阪 時間不明 → 癸酉（正しくは甲戌） | 段階1で修正（時間不明なら補正しない） |
| 3 | **奇門遁甲の日盤が必ずエラーになる** | 日盤が使えない | 実測：500エラー | 段階1で修正 |
| 4 | マイページの「自分の命式」が、性別を男性に固定して作る | 女性会員の本人の大運の向きが誤る（大運は本番では非表示） | コード（`MyPage.js` 225行） | 段階1で修正（プロフィールの性別を使う） |
| 5 | 1901年1月1日〜5日の生まれはエラーになる | 前年の節入りデータがない | 調査報告 | 入力の範囲から外し、理由を表示 |
| 6 | 日柱の予備処理の基準日が誤っている（1900-01-01 を甲子としているが実際は甲戌） | 通常は使われない処理 | コード | 新版では予備処理を設けない |
| 7 | 均時差が月ごとの固定値。補正後の太陽時と、日本標準時の節入り時刻をそのまま比べている | 節入りの前後数十分で、月柱・年柱が揺れる可能性 | 推測 | 正解データで確かめてから判断 |
| 8 | 奇門遁甲の局数データが2026年分しかない | 2027年以降は自動で作盤できない | データ | 段階1までにデータを用意（要確認） |

## B.2 使いやすさの課題

| # | 内容 | 根拠 | 新版での対応 |
|---|---|---|---|
| 1 | 判定の要点の生成に約30秒かかり、その間は何も表示されない | `SkillReport.js` | 進み具合の表示（段階1）、文章を順に表示（段階2） |

| 11 | スマートフォン対応が一部の画面だけ。ヘッダーは折り返すだけ | 各 CSS | スマートフォン基準で設計し、下部タブを置く |
| 12 | 履歴で、時間不明の記録も「0時」と表示される。氏名が空だと「 さんの鑑定表」になる | `HistoryPage.js`、`DetailPage.js` | 表示を修正 |

| 16 | 解説のモーダルが Esc で閉じない。キーボードで通変星を開けない | `StemModal.js`、`DetailPage.js` | アクセシビリティの決まり（05_表層） |
| 17 | マイページに5つの機能が1画面に並ぶ。表示モードの変更に失敗しても元に戻らない | `MyPage.js` | 項目ごとの画面に分ける |
| 18 | 印刷・PDF の機能がない | — | 段階2 |
| 19 | 大運・年運が本番で見えない | `serializers.py`（DEBUG のときだけ） | 正解データでの確認後に公開を判断 |
| 20 | トップページが説明1行だけ。塾名も出てこない | `HomePage.js` | 紹介ページ |

## B.3 セキュリティ・運用の課題

| # | 内容 | 新版での対応 |
|---|---|---|
| 1 | ログイン・登録に回数制限がない。パスワードリセットの回数制限も、プロセスごとのメモリで数えていて実際の上限が約3倍になり、送信元IPの偽装ですり抜けられる | Supabase Auth の回数制限を使う |
| 2 | パスワード変更で、現在のパスワードを確認しない | 確認する |
| 3 | トークンの更新処理で新しいトークンを保存していない。トークンを無効にする仕組み（ブラックリスト）がない | Supabase Auth に任せる |
| 4 | 退会しても、プロフィール・鑑定記録・判定の要点が残る | 退会したら削除する |
| 5 | 管理者だけの画面の判定が画面側に頼る部分があり、判定前に一瞬画面が描画される | サーバー側と RLS で判定する |
| 6 | CSP（Content-Security-Policy）が設定されていない | 設定する |
| 7 | `DEBUG` と `SECRET_KEY` の既定値が危険（環境変数を設定し忘れると、本番がデバッグモードで動く） | 新版では該当しない。環境変数は必須にし、未設定なら起動を止める |
| 8 | リポジトリのルートに `.gitignore` がなく、`.env.prod` が Git の除外対象になっていない（今は管理対象外だが、誤ってコミットされるおそれ） | 新版のリポジトリでは最初に除外設定を入れる。**現行でもすぐに対処を推奨** |
| 9 | 起動のたびにマイグレーションファイルを自動で作っている（`entrypoint.sh`） | マイグレーションはファイルで管理し、手順を固定する |
| 10 | データベースの定期バックアップがない（手動の手順だけ） | Supabase の自動バックアップ |
| 11 | CI/CD のドキュメントはあるが、実際のワークフロー（`.github/`）は存在しない | プルリクエストごとの自動テストを実際に用意する |
| 12 | `fortune/tests.py`（32件）が、同名の `fortune/tests/` パッケージに隠れて実行されていない可能性が高い。セキュリティチェックリストが根拠にしているテストを含む | 新版でテストを移植するとき、内容を確認して取り込む |

## B.4 ドキュメントと実装のずれ

新版の仕様は、この新仕様書を正とします。現行の `doc/` は参考資料として扱い、次のずれに注意してください。

| ドキュメント | ずれ |
|---|---|
| `doc/四柱推命計算ロジック.md` | 月柱を計算式で出す・日柱を1900年起点で出すなど古い記述。年柱の立春の切り替えが書かれていない |
| `doc/節月ガイド.md` | CSV を読むと書いているが、実際は `solar_terms.json` |
| `doc/バックエンド構成.md` | 多くの API・モデルの項目が載っていない。存在しないインデックスが書かれている |
| `doc/フロントエンド構成.md` | 存在しない共有機能、ヘッダーのユーザー名表示、生年の範囲（1900〜2100。実装は1901〜2040） |
| `doc/CI_CD_ガイド.md` | 書かれたワークフローが存在しない |
| 都道府県の表記 | ドキュメントは「都道府県補正」、実装は47都市（埼玉は「浦和」） |
| 身旺身弱の同点 | 画面は「-」、スキル表は「中和」 |

`doc/鑑定スキル表.md`、`doc/解釈ルール設定.md`、`doc/判定の要点生成.md` は、確認した範囲では実装と一致しています。

## B.5 使われていないもの

新版には引き継ぎません。

- 画面側：`useFortuneDetail`、`useFortuneHistory`（存在しない関数を呼んでいる）、`utils/validation.js`、`isFortuneteller`
- API：`/api/fortune/share/{id}/`（共有の実体がない）
- 画像：`public/img` の五行・太極・十二支の8点
- 処理：`get_solar_month`（どこからも呼ばれていない）
