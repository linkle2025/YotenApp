## この仕様書の目的

今のアプリ（React＋Django＋PostgreSQL、さくらVPS上の Docker と Nginx で稼働）を、サーバー管理のいらない構成に作り直します。

作り直しにあたって、**使いやすさ（UX）を最優先**にします。そのため、画面から書き始めるのではなく、UXの5段階モデル（Jesse James Garrett『The Elements of User Experience』）に沿って、抽象的な「なぜ作るか」から具体的な「どう見せるか」の順に決めていきます。

| 段階 | ファイル | 決めること |
|---|---|---|
| 1. 戦略 | [01_戦略.md](./01_戦略.md) | 誰の、どんな目的のためのアプリか。事業としての狙い。成功の物差し |
| 2. 要件 | [02_要件.md](./02_要件.md) | 何を作るか（機能・コンテンツ・非機能）。何を作らないか。優先順位 |
| 3. 構造 | [03_構造.md](./03_構造.md) | 情報の分類と画面の構成、画面遷移、ユーザーの流れ、権限、データの形 |
| 4. 骨格 | [04_骨格.md](./04_骨格.md) | 画面ごとの配置（ワイヤーフレーム）、ナビゲーション、部品 |
| 5. 表層 | [05_表層.md](./05_表層.md) | 色・文字・余白などの見た目、文章のトーン、アクセシビリティ |

下の段階は、上の段階の決定に従います。上の段階を変えたときは、下の段階も見直してください。

## 決定済みの前提

2026-11 のやりとりで決めたことです。仕様書全体の前提になります。

| 項目 | 決定内容 |
|---|---|
| 構成 | Next.js（App Router）を Vercel で動かす。データと認証は Supabase（PostgreSQL・Auth）。サーバーの管理はしない |
| 作り直しの範囲 | 画面・処理ともに全面的に作り直す。四柱推命の計算ロジックも TypeScript に移植する |
| 最優先 | 使いやすさ（UX） |
| 会員の移行 | しない。今はα版で会員は身内だけのため、新版で全員に登録し直してもらう |
| ダウンタイム | 長くてもよい |
| 管理画面 | Django 標準の管理画面は使っていないので、引き継がない。必要な管理機能は新版の中に作る |
| 集客 | 将来、集客が必要になる。検索に強い公開ページ（SEO）を前提にする |
| 鑑定結果の正しさ | 今の結果もまだ精査が必要。お手本サイト（会員制）の結果と手作業で照合して、正解データを作る（[付録D](./付録D_正解データ用テストケース.md)） |
| 23時台の生まれ | お手本サイトの扱いに合わせる |
| 奇門遁甲 | 当面は管理者だけが使う。一般にも会員にも公開しない |
| ログイン | メールアドレスとパスワードで行う（現行のユーザー名はやめる） |

## 用語

| 用語 | 意味 |
|---|---|
| 命式 | 生年月日時から出す、年柱・月柱・日柱・時柱の4つの干支の組み合わせ |
| 日干 | 日柱の天干。その人自身を表し、鑑定の起点になる |
| 鑑定記録 | 1回の命式作成の入力と結果。現行の「履歴」。自分の分も、他人の分も作れる |
| 鑑定表 | 鑑定記録の詳細画面。命式・五行バランス・鑑定スキル表・判定の要点を表示する |
| 鑑定スキル表 | 命式から、9つの能力と7つの職種適性を点数とランクで示す表 |
| 判定の要点 | 鑑定スキル表の点数の根拠を、AI（Gemini）が文章で説明したもの |
| 解釈ルール | AIの読み方と点数補正を決める設定。現行は `skill_rules.toml` |
| 奇門遁甲 | 時刻・方位の吉凶を盤で見る占術。管理者だけが使う |
| お手本サイト | 鑑定結果の正しさを照合する基準にする外部の会員制サイト。結果は手作業で写す |
| 正解データ | お手本サイトの結果を集めた照合用の表。移植のテストに使う |
