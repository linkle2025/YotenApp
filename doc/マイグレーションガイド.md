# マイグレーションガイド

## データベーススキーマの更新

### 問題
命式作成時に以下のいずれかのエラーが発生する場合：
```
column "birth_minute" of relation "fortune_fortunecalculation" does not exist
column "hour_unknown" of relation "fortune_fortunecalculation" does not exist
```

### 解決方法

#### 方法1: シェルスクリプトを使用（推奨）

```bash
cd /Users/ishikawa/Library/CloudStorage/Dropbox/cursor/YotenApp
./apply_migrations.sh
```

#### 方法2: 手動でマイグレーションを実行

Dockerコンテナが起動している場合：

```bash
cd /Users/ishikawa/Library/CloudStorage/Dropbox/cursor/YotenApp
docker-compose exec backend python manage.py migrate fortune
```

#### 方法3: コンテナを再起動

```bash
cd /Users/ishikawa/Library/CloudStorage/Dropbox/cursor/YotenApp
docker-compose down
docker-compose up -d
```

コンテナ起動時に自動的にマイグレーションが実行されます（entrypoint.shで設定済み）。

### マイグレーション内容

#### 0006_fortunecalculation_birth_minute
- `FortuneCalculation`モデルに`birth_minute`フィールドを追加
- デフォルト値: 0
- 既存データには自動的に`birth_minute=0`が設定されます

#### 0007_fortunecalculation_hour_unknown
- `FortuneCalculation`モデルに`hour_unknown`フィールドを追加
- デフォルト値: False
- 時間不明の場合、時柱は空欄で保存されます

### 確認方法

マイグレーション適用後、以下のコマンドで確認できます：

```bash
docker-compose exec backend python manage.py showmigrations fortune
```

出力例：
```
fortune
 [X] 0001_initial
 [X] 0002_fortunecalculation_name_and_more
 [X] 0003_fortunecalculation_day_pillar_hidden_stem_and_more
 [X] 0004_fortunecalculation_day_pillar_hidden_stem_secondary_and_more
 [X] 0005_fortunecalculation_day_pillar_heavenly_stem_star_and_more
 [X] 0006_fortunecalculation_birth_minute  ← この行が[X]になっていればOK
 [X] 0007_fortunecalculation_hour_unknown  ← この行が[X]になっていればOK
```

## トラブルシューティング

### マイグレーションが適用されない場合

1. バックエンドコンテナが起動しているか確認：
```bash
docker-compose ps
```

2. バックエンドのログを確認：
```bash
docker-compose logs backend
```

3. データベースコンテナが起動しているか確認：
```bash
docker-compose ps db
```

### エラーが解決しない場合

データベースをリセット（**注意：すべてのデータが削除されます**）：

```bash
docker-compose down -v
docker-compose up -d
```

これにより、データベースが初期化され、すべてのマイグレーションが最初から適用されます。
