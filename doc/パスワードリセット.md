# パスワードリセット（メール送信）

ログイン画面の「パスワードを忘れた場合」から、登録メールアドレス宛てにパスワード再設定用のリンクを送る機能です。

## 流れ

1. ログイン画面 →「パスワードを忘れた場合」→ `/password-reset`（ForgotPasswordPage）でメールアドレスを入力
2. バックエンドが該当ユーザーにメールを送信（リンク: `{FRONTEND_URL}/password-reset/<uid>/<token>`）
3. リンクを開くと `/password-reset/:uid/:token`（ResetPasswordPage）が表示され、まずリンクの有効性を確認
4. 新しいパスワードを2回入力して再設定 → ログイン画面へ

ログインはユーザー名で行うため、メール本文にユーザー名も載せています。

## API

| メソッド | エンドポイント | 内容 | 認証 |
|---------|--------------|------|-----|
| POST | `/api/auth/password-reset/` | `{email}` を受け取り、該当ユーザーにメールを送る | 不要 |
| POST | `/api/auth/password-reset/confirm/` | `{uid, token}` でリンクの有効性を確認。`password`・`password2` も渡すと再設定 | 不要 |

- 依頼 API は、登録の有無にかかわらず常に同じ 200 応答を返す（メールアドレスの登録状況を外から調べられないようにするため）。メール形式が不正なときだけ 400
- 確認 API は、リンクが無効・期限切れなら 400 `{detail}`、パスワードが規則に合わなければ 400 `{password: [...]}`
- 実装: `backend/apps/accounts/password_reset.py`（メール作成・トークン確認）、`views.py` の `password_reset_request` / `password_reset_confirm`

## セキュリティ上の扱い

- トークンは Django 標準の `default_token_generator`。DB には何も保存しない
  - パスワードを変えるとトークンの元の値が変わるため、**一度使ったリンクは無効**になる
  - 有効期限は `PASSWORD_RESET_TIMEOUT`（既定 3600 秒＝60分）
- 対象は「有効（`is_active`）で、パスワードが設定済み」のユーザーだけ。退会済みユーザーには送らない
- 同じメールアドレスのユーザーが複数いる場合は、それぞれのユーザー名入りのメールを1通ずつ送る
- メールアドレスは大文字・小文字を区別せずに照合する
- 新しいパスワードは登録時と同じ Django のパスワード規則（8文字以上、よくある語句・数字のみ・ユーザー名に似たものは不可）
- 回数制限（IP 単位、DRF の ScopedRateThrottle）: 依頼 5回/時（`PASSWORD_RESET_THROTTLE_RATE` で変更可）、確認 20回/時。超えると 429
- 送信失敗は応答に出さず、ログ（`apps.accounts.password_reset`）にだけ残す
- 再設定しても、すでに発行済みのログイン用 JWT は有効期限（アクセス1時間・リフレッシュ7日）まで残る（JWT のブラックリストは未導入）

## 設定（環境変数）

| 変数 | 既定値 | 内容 |
|------|-------|------|
| `EMAIL_BACKEND` | `django.core.mail.backends.console.EmailBackend` | 開発はコンソール出力。本番は `django.core.mail.backends.smtp.EmailBackend` |
| `EMAIL_HOST` / `EMAIL_PORT` | `localhost` / `587` | SMTP サーバー（yoten.app のメールサーバー。例は `mail.yoten.app`） |
| `EMAIL_HOST_USER` / `EMAIL_HOST_PASSWORD` | 空 | SMTP の認証情報（Git に入れない） |
| `EMAIL_USE_TLS` / `EMAIL_USE_SSL` | `True` / `False` | 587番は TLS、465番は SSL（両方 True は不可） |
| `EMAIL_TIMEOUT` | `20` | SMTP 接続のタイムアウト（秒） |
| `DEFAULT_FROM_EMAIL` | `陽てん塾 <noreply@yoten.app>` | 送信元。SMTP サービス側で送信を許可したアドレスにする |
| `FRONTEND_URL` | `http://localhost:3000` | メール内リンクの宛先。本番は `https://app.yoten.org` |
| `PASSWORD_RESET_TIMEOUT` | `3600` | リンクの有効期限（秒） |
| `PASSWORD_RESET_THROTTLE_RATE` | `5/hour` | 依頼 API の回数制限 |

### 開発環境での確認

`backend/.env` の `EMAIL_BACKEND` が console（既定）の間は、メールは送信されず、バックエンドのログに本文が出ます。
yoten.app のメールサーバーから実際に送って確かめるときは、`backend/.env` の `EMAIL_BACKEND` を smtp の行に切り替え、`EMAIL_HOST_PASSWORD` などを埋めてから `docker compose restart backend` を実行します。

```bash
docker compose logs -f backend   # 「パスワード再設定のご案内」の本文中のリンクを開く
```

### 本番環境

`.env.prod` に SMTP の設定と `FRONTEND_URL` を書き、バックエンドを再作成します（[VPSデプロイガイド.md](./VPSデプロイガイド.md) の 3.3）。
迷惑メール扱いを避けるため、送信元ドメイン（yoten.app）に SPF・DKIM を設定してください。
