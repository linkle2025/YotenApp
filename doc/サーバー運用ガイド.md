# サーバー運用ガイド

## Docker コマンド

### 基本操作

```bash
# 起動（バックグラウンド）
# 本番サーバーでは必ず docker-compose.prod.yml と .env.prod を使用すること（ポート競合・データ消失を防ぐ）
docker-compose up -d

# 起動（フォアグラウンド、ログ表示）
docker-compose up

# 再ビルドして起動
docker-compose up --build -d
## 本番環境ではフロントエンドの変更時、コンテナを再ビルドして、新しいイメージでコンテナを起動し直す必要があります。
docker compose -f docker-compose.prod.yml --env-file .env.prod build --no-cache frontend && \
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --force-recreate frontend


docker compose -f docker-compose.prod.yml --env-file .env.prod build --no-cache backend && \
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --force-recreate backend

# 停止
docker-compose stop

# 停止して削除
docker-compose down

# 完全削除（データベースボリュームも削除）
docker-compose down -v

# コンテナの状態確認
docker-compose ps
```

---

### ログ確認

```bash
# 全サービスのログ
docker-compose logs -f

# 特定のサービスのみ
docker-compose logs -f backend
docker-compose logs -f frontend
docker-compose logs -f db

# 最後の100行を表示
docker-compose logs --tail=100 backend
```

---

### コンテナ内でコマンド実行

```bash
# バックエンド（Django）
docker-compose exec backend python manage.py shell
docker-compose exec backend python manage.py createsuperuser
docker-compose exec backend python manage.py migrate

# フロントエンド
docker-compose exec frontend npm install
docker-compose exec frontend npm audit fix

# PostgreSQL
docker-compose exec db psql -U postgres -d yotenapp
```

## データベース管理

### PostgreSQLへの接続

```bash
# コンテナ内から接続
docker exec -it yotenapp_postgres psql -U postgres -d yotenapp
```

### よく使うSQLコマンド

```sql
-- テーブル一覧
\dt

-- テーブル構造確認
\d fortune_fortunecalculation

-- データベース一覧
\l

-- ユーザー一覧
SELECT * FROM auth_user;

-- 計算履歴一覧
SELECT id, user_id, birth_year, birth_month, birth_day, created_at 
FROM fortune_fortunecalculation 
ORDER BY created_at DESC 
LIMIT 10;

-- 終了
\q
```

---

### データベースバックアップ

```bash
# バックアップ作成
docker exec yotenapp_postgres pg_dump -U postgres yotenapp > backup_$(date +%Y%m%d_%H%M%S).sql

# バックアップから復元
docker exec -i yotenapp_postgres psql -U postgres yotenapp < backup_20250115_100000.sql
```

## トラブルシューティング

### コンテナが起動しない

```bash
# ログを確認
docker-compose logs backend
docker-compose logs db

# コンテナを完全に削除して再作成
docker-compose down
docker-compose up --build -d
```

---

### データベース接続エラー

```bash
# PostgreSQLコンテナの状態確認
docker-compose ps db

# PostgreSQLのログ確認
docker-compose logs db

# データベース接続テスト
docker-compose exec backend python manage.py dbshell
```

---

### フロントエンドの変更が反映されない

```bash
# フロントエンドコンテナを再起動
docker-compose restart frontend

# 環境変数を変更した場合は再ビルド
docker-compose stop frontend
docker-compose rm -f frontend
docker-compose up --build -d frontend
```

---

### ポートが既に使用されている

```bash
# 使用中のポートを確認
lsof -i :8000  # バックエンド
lsof -i :3000  # フロントエンド
lsof -i :5432  # PostgreSQL

# 該当プロセスを停止するか、docker-compose.ymlのポート番号を変更
```

## 開発ワークフロー

### 1. 初回セットアップ

```bash
# リポジトリをクローン
git clone <repository_url>
cd YotenApp

# Docker起動
docker-compose up --build -d

# マイグレーション実行（自動実行されますが、確認用）
docker-compose exec backend python manage.py migrate

# スーパーユーザー作成
docker-compose exec backend python manage.py createsuperuser

# ブラウザでアクセス
# フロントエンド: http://localhost:3000
# 管理画面: http://localhost:8000/admin/
```

---

### 2. 日常的な開発

```bash
# 起動
docker-compose up -d

# ログ監視（別ターミナル）
docker-compose logs -f

# 開発...

# 停止
docker-compose down
```

---

### 3. モデル変更時

```bash
# マイグレーションファイル作成
docker-compose exec backend python manage.py makemigrations

# マイグレーション実行
docker-compose exec backend python manage.py migrate
```

---

### 4. パッケージ追加時

```bash
# バックエンド（requirements.txt編集後）
docker-compose up --build -d backend

# フロントエンド（package.json編集後）
docker-compose up --build -d frontend
```

## 本番環境への展開

**注意**: 現在の設定は開発環境用です。本番環境では以下の変更が必要です：

1. **セキュリティ設定**
   - `SECRET_KEY` を強力なランダム文字列に変更
   - `DEBUG = False` に設定
   - `ALLOWED_HOSTS` を適切に設定

2. **データベース**
   - 強力なパスワードを設定
   - データボリュームのバックアップ設定

3. **Webサーバー**
   - Gunicorn/uWSGI を使用
   - Nginx をリバースプロキシとして配置

4. **静的ファイル**
   - `collectstatic` を実行
   - Nginx で配信

5. **HTTPS対応**
   - SSL証明書の設定（Let's Encrypt推奨）

## トラブルシューティング

### 新規登録画面に性別欄が出ない場合の切り分け

性別欄は**フロントエンド**の変更のため、`migrate` だけでは表示されません。以下を順に確認してください。

#### ステップ1: サーバー上のソースに性別の変更が含まれているか確認

本番サーバーで、リポジトリの状態を確認します。

```bash
# 本番サーバー上で
cd /path/to/YotenApp   # アプリのルートへ

# 最新を取得済みか・性別(gender)の追加が含まれているか
grep -n "gender" frontend/src/pages/RegisterPage.js | head -5
```

- **期待**: `useState('male')` や `setGender`、`性別` などの行が複数出る。
- **出ない場合**: `git pull` が未実行、または別ブランチ・別ディレクトリで作業している可能性があります。正しいブランチで `git pull origin main`（または `develop`）を実行し、再度確認してください。

---

#### ステップ2: フロントエンドを再ビルドし、新しいイメージでコンテナを起動し直す

性別欄は React の変更なので、**イメージの再ビルド**と**コンテナの再作成**が必要です。`migrate` はバックエンドのDBのみで、フロントの配信内容は変わりません。

本番サーバーで次を実行します。

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod build --no-cache frontend && \
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --force-recreate frontend
```

- **確認**: ブラウザで新規登録画面を**強制再読込**（Ctrl+Shift+R / Cmd+Shift+R）して、性別欄の有無を確認します。

---

#### ステップ3: ブラウザのキャッシュを除外して確認

ステップ2後も表示されない場合、古い JavaScript がキャッシュされている可能性があります。

1. **シークレット（プライベート）ウィンドウ**で新規登録ページを開く。  
   または  
2. 開発者ツール（F12）を開き、**ネットワーク**タブで「キャッシュを無効化」にチェックを入れた状態で再読込する。

- それでも出ない場合は、ステップ1に戻り、`RegisterPage.js` に性別関連のコードが本当に含まれているか再確認してください。

---

#### ステップ4: 配信されている JS に性別が含まれているか確認（上級者向け）

ブラウザの開発者ツールで、新規登録ページを開いた状態で:

1. **ソース**（または **Sources**）タブを開く。
2. ページが読み込んでいる `static/js/main.*.js`（または `*.chunk.js`）を開く。
3. 検索（Ctrl+F / Cmd+F）で `性別` や `gender` を検索する。

- **見つかる**: フロントのビルドは新しいが、表示だけ別要因（CSSで隠れている等）の可能性があります。
- **見つからない**: まだ古いビルドが配信されています。ステップ2を再度実行し、`build --no-cache` でビルドし直したうえで、`--force-recreate` で frontend コンテナを起動し直してください。
