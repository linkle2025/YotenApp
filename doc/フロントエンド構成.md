## ルーティング構成

| パス | コンポーネント | 認証要否 | 説明 |
|------|--------------|---------|------|
| `/` | HomePage | 不要 | トップページ |
| `/login` | LoginPage | 不要 | ログインページ |
| `/register` | RegisterPage | 不要 | ユーザー登録ページ |
| `/password-reset` | ForgotPasswordPage | 不要 | パスワード再設定メールの申し込み |
| `/password-reset/:uid/:token` | ResetPasswordPage | 不要 | メールのリンクから新しいパスワードを設定 |
| `/calculate` | CalculatePage | **必要** | 四柱推命計算フォーム |
| `/history` | HistoryPage | **必要** | 計算履歴一覧 |
| `/fortune/:id` | DetailPage | **必要** | 計算結果詳細表示 |

※ 認証が必要なルートは `PrivateRoute` コンポーネントで保護されています。

## ページ詳細

### 1. HomePage（トップページ）

**パス**: `/`  
**認証**: 不要

**機能**:
- アプリケーションの説明表示
- ユーザーの認証状態に応じて表示を切り替え
  - 未ログイン: 「アカウント作成」「ログイン」ボタン表示
  - ログイン済み: 「計算する」「履歴を見る」ボタン表示

**使用API**: なし

---

### 2. LoginPage（ログインページ）

**パス**: `/login`  
**認証**: 不要

**機能**:
- ユーザー名とパスワードによるログイン
- JWT トークンの取得と保存（localStorage）
- ログイン成功後、トップページへリダイレクト

**フォーム項目**:
- ユーザー名
- パスワード

**使用API**:
- `POST /api/token/` - ログイン、JWTトークン取得

「パスワードを忘れた場合」のリンクから ForgotPasswordPage へ進めます。

---

### パスワードリセット（ForgotPasswordPage / ResetPasswordPage）

**パス**: `/password-reset`、`/password-reset/:uid/:token`  
**認証**: 不要

- ForgotPasswordPage: メールアドレスを入力して再設定メールを申し込む。送信後は API が返す共通メッセージを表示（登録の有無は表示しない）
- ResetPasswordPage: 開いた時点でリンクの有効性を確認し、有効なら新しいパスワード（2回入力）のフォーム、無効なら再申し込みへのリンクを表示
- スタイルは `LoginPage.css` を共用
- 詳細: [パスワードリセット.md](./パスワードリセット.md)

---

### 3. RegisterPage（ユーザー登録ページ）

**パス**: `/register`  
**認証**: 不要

**機能**:
- 新規ユーザーの登録
- パスワード確認（2回入力）
- 登録成功後、トップページへリダイレクト

**フォーム項目**:
- ユーザー名
- メールアドレス
- パスワード
- パスワード（確認）

**バリデーション**:
- パスワードと確認用パスワードの一致確認

**使用API**:
- `POST /api/auth/register/` - ユーザー登録

---

### 4. CalculatePage（四柱推命計算ページ）

**パス**: `/calculate`  
**認証**: **必要**

**機能**:
- 生年月日時、都道府県、性別を入力して四柱推命を計算
- 氏名の入力（任意）
- 計算結果を自動的に保存
- 計算完了後、結果詳細ページへ自動遷移
- 都道府県による経度差を考慮した時刻補正

**フォーム項目**:
- 氏名（任意、最大100文字）
- 生年（1900-2100）
- 生月（1-12）
- 生日（1-31）
- 生時（0-23時）
- 生まれた都道府県（必須、47都道府県から選択）
- 性別（男性/女性）

**使用API**:
- `POST /api/fortune/calculate/` - 四柱推命計算

---

### 5. HistoryPage（計算履歴一覧ページ）

**パス**: `/history`  
**認証**: **必要**

**機能**:
- ログインユーザーの計算履歴一覧を表示
- 各履歴項目をクリックして詳細表示へ遷移
- 履歴の削除機能
- お気に入り登録/解除機能

**表示情報**:
- 氏名（入力されている場合のみ）
- 計算日時
- 生年月日時
- 生まれた都道府県
- お気に入り状態

**使用API**:
- `GET /api/fortune/history/` - 履歴一覧取得
- `DELETE /api/fortune/history/{id}/delete/` - 履歴削除
- `PATCH /api/fortune/history/{id}/favorite/` - お気に入り切り替え

---

### 6. DetailPage（計算結果詳細ページ）

**パス**: `/fortune/:id`  
**認証**: **必要**

**機能**:
- 指定IDの四柱推命計算結果を表示
- 四柱（年柱、月柱、日柱、時柱）の表示
- 大運の表示
- 鑑定スキル表と判定の要点の表示・生成（`SkillReport` コンポーネント）
- お気に入り登録/解除機能

**レイアウト**（2026-11-05 に横長へ変更）:
- 画面全幅（最大1920px）を使う。セクション見出しは付けない
- 上部に「◯◯さんの鑑定表」、その右に日干アイコン付きの「日干：己（田畑）」（クリックで十干の説明）、右端に生年月日・性別・出生地
- 768px 以上は2列。左サイド（360px、1200px 以上は400px）に命式と五行バランス、右メインに `SkillReport`（要約 → 能力3×3 → 職種ごとのランクと解説 → 活かし方）
- 左サイドはスクロールに追従する（`position: sticky`。サイドが画面より高い場合は下端が見えた位置で止まるよう、`top` を JS で計算）
- 五行バランス図は CSS の `zoom` で縮小し、吹き出しと解説文だけ元の大きさに戻す
- 右メインはコンテナクエリで段組みを切り替える（能力は幅560px以上で3列、職種は800px以上で2列）
- 767px 以下は従来どおり縦一列。大運・年運（開発環境のみ）はページ下部に置き、1200px 以上で横に並べる
- 計算デバッグ情報（五行バランス・鑑定スキル表・大運）は `DetailPage.js` の `SHOW_DEBUG_INFO`（既定 `false`）で表示を切り替える

**表示情報**:
- 氏名（入力されている場合のみ）
- 生年月日時
- 生まれた都道府県
- 性別
- 四柱（天干・地支）
- 計算日時

**使用API**:
- `GET /api/fortune/history/{id}/` - 詳細取得
- `PATCH /api/fortune/history/{id}/favorite/` - お気に入り切り替え
- `GET / POST /api/fortune/history/{id}/skill-insight/` - 判定の要点の取得・生成

## コンポーネント詳細

### Header（ヘッダーコンポーネント）

**機能**:
- 全ページ共通のヘッダー表示
- ロゴ（クリックでトップページへ）
- ナビゲーションメニュー
- 認証状態に応じた表示切り替え

**ログイン済みの場合**:
- 「計算」「履歴」リンク
- ユーザー名表示
- 「ログアウト」ボタン

**未ログインの場合**:
- 「ログイン」リンク
- 「登録」リンク

---

### SkillReport（鑑定スキル表＋判定の要点）

**機能**:
- `useSkillInsight` フック（`hooks/useSkillInsight.js`）で、ページを開いたときに保存済みの判定の要点を取得する（自動生成はしない）
- 上から、要約（未生成なら「判定の要点を生成」ボタン）→ `SkillSheet` → 活かし方 → 注記・モデル名・生成日時
- 生成は最初の1回のみ。「再生成」ボタンは当面非表示（API の `regenerate=true` は残している）
- 生成中は `Loading`、エラー時は `ErrorMessage` を表示
- 機能が無効なとき（API の `available=false`）は、ボタンの代わりにメッセージを表示

**使用箇所**: DetailPage（右メイン）

---

### SkillSheet（鑑定スキル表の表示部分）

**機能**:
- API の `skill_sheet` を表示する。能力9項目は3×3のカード（点数の高い順）、職種7項目は「職種名（意味）　ランク」（S から降順）。同点は API の表示順を保つ
- `insight` を渡すと、職種・能力ごとの解説文を各項目の下に表示する（ランクは `skill_sheet` の値。LLM の本文には含めない）
- 文言はハードコードせず API の値を表示する。`skill_sheet` が null の場合は何も表示しない
- `showDebug` が true（管理者）のとき、折りたたみの計算デバッグ情報を表示

詳細は [鑑定スキル表.md](./鑑定スキル表.md)、[判定の要点生成.md](./判定の要点生成.md) を参照。

---

### PrivateRoute（認証保護ルート）

**機能**:
- 認証が必要なページへのアクセスを制御
- 未認証の場合、自動的にログインページへリダイレクト
- JWTトークンの存在をチェック

**使用箇所**:
- `/calculate`
- `/history`
- `/fortune/:id`

## Context（状態管理）

### AuthContext

**提供する機能**:
- ユーザー情報の管理
- ログイン/ログアウト処理
- ユーザー登録処理
- 認証状態の確認

**提供する値**:
- `user`: 現在のユーザー情報（`null`の場合は未認証）
- `login(username, password)`: ログイン関数
- `logout()`: ログアウト関数
- `register(username, email, password, password2)`: 登録関数

**実装詳細**:
- 初回レンダリング時に自動的に現在のユーザー情報を取得
- トークンが存在する場合、`/api/auth/user/` から情報を取得
- 全コンポーネントから `useAuth()` フックでアクセス可能

## サービス層（API通信）

### api.js（Axios設定）

**機能**:
- Axiosインスタンスの作成と設定
- ベースURL: `http://localhost:8000/api`
- リクエスト/レスポンスインターセプター

**リクエストインターセプター**:
- 全リクエストに自動的にJWTトークンを`Authorization`ヘッダーに追加

**レスポンスインターセプター**:
- 401エラー（認証エラー）発生時、自動的にトークンリフレッシュを試行
- リフレッシュ成功: 元のリクエストを再送
- リフレッシュ失敗: ログアウトしてログインページへリダイレクト

---

### authService.js（認証API）

**提供する関数**:

| 関数 | エンドポイント | 説明 |
|------|--------------|------|
| `register(username, email, password, password2)` | `POST /api/auth/register/` | ユーザー登録 |
| `login(username, password)` | `POST /api/token/` | ログイン、トークン取得 |
| `getCurrentUser()` | `GET /api/auth/user/` | 現在のユーザー情報取得 |
| `logout()` | - | ローカルストレージのトークン削除 |
| `isAuthenticated()` | - | 認証状態の確認 |
| `requestPasswordReset(email)` | `POST /api/auth/password-reset/` | パスワード再設定メールの申し込み |
| `checkPasswordResetLink(uid, token)` | `POST /api/auth/password-reset/confirm/` | リセット用リンクの有効性確認 |
| `confirmPasswordReset(uid, token, password, password2)` | `POST /api/auth/password-reset/confirm/` | パスワード再設定 |

---

### fortuneService.js（四柱推命API）

**提供する関数**:

| 関数 | エンドポイント | 説明 |
|------|--------------|------|
| `calculate(year, month, day, hour, prefecture, gender, name)` | `POST /api/fortune/calculate/` | 四柱推命計算（name は任意） |
| `getHistory(favorite)` | `GET /api/fortune/history/` | 計算履歴一覧取得（favorite でフィルタ可能） |
| `getDetail(id)` | `GET /api/fortune/history/{id}/` | 計算結果詳細取得 |
| `deleteCalculation(id)` | `DELETE /api/fortune/history/{id}/delete/` | 履歴削除 |
| `toggleFavorite(id)` | `PATCH /api/fortune/history/{id}/favorite/` | お気に入り切り替え |
| `getSkillInsight(id)` | `GET /api/fortune/history/{id}/skill-insight/` | 判定の要点（保存済みの最新）を取得 |
| `generateSkillInsight(id, {regenerate})` | `POST /api/fortune/history/{id}/skill-insight/` | 判定の要点を生成 |
| `shareCalculation(id)` | `GET /api/fortune/share/{id}/` | 共有URL生成 |

## ユーティリティ（utils/）

### constants.js（定数）

**PREFECTURES**:
- 日本の47都道府県のリスト
- `CalculatePage` で都道府県選択フィールドに使用
- 配列形式: `['北海道', '青森県', ..., '沖縄県']`

**使用例**:
```javascript
import { PREFECTURES } from '../utils/constants';

<select value={prefecture} onChange={(e) => setPrefecture(e.target.value)}>
  {PREFECTURES.map((pref) => (
    <option key={pref} value={pref}>{pref}</option>
  ))}
</select>
```

### dateFormat.js（日付フォーマット）

**formatDate(dateString)**:
- ISO形式の日付文字列を `YYYY年MM月DD日 HH:MM` 形式に変換
- 使用例: `formatDate('2024-01-01T12:00:00Z')` → `'2024年01月01日 12:00'`

### validation.js（バリデーション）

**validateBirthDate(year, month, day)**:
- 生年月日の妥当性をチェック
- 無効な場合はエラーメッセージを返す

**validateBirthHour(hour)**:
- 生時の妥当性をチェック（0-23）
- 無効な場合はエラーメッセージを返す

## 開発時の注意事項

### コードの自動反映

Docker環境では、以下のファイルの変更は自動的に反映されます：
- `.js`、`.jsx` ファイル
- `.css` ファイル
- `.html` ファイル

再ビルドが必要な場合：
- `package.json` の変更
- `REACT_APP_*` 環境変数の変更
- `Dockerfile` の変更

```bash
# フロントエンドのみ再ビルド
docker-compose up --build -d frontend
```

### ブラウザキャッシュ対策

開発中にキャッシュが原因で変更が反映されない場合：
- ハードリフレッシュ: `Cmd + Shift + R` (Mac) / `Ctrl + Shift + R` (Windows)
- シークレットモードでテスト
- 開発者ツールで「Disable cache」を有効化
