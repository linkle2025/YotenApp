# テストガイド

## 概要

このプロジェクトでは、バックエンド（Django）とフロントエンド（React）の両方でテストを実装しています。

## バックエンドテスト（Django）

### テストの実行

```bash
# Docker環境
docker-compose exec backend python manage.py test

# ローカル環境
cd backend
python manage.py test

# 特定のアプリのみテスト
python manage.py test apps.accounts
python manage.py test apps.fortune

# 特定のテストケースのみ実行
python manage.py test apps.accounts.tests.UserRegistrationTests
```

### カバレッジレポート

```bash
# カバレッジ計測
pip install coverage
coverage run --source='.' manage.py test
coverage report

# HTML形式で出力
coverage html
# htmlcov/index.html をブラウザで開く
```

### テストの構成

#### accounts アプリ

**UserRegistrationTests**: ユーザー登録のテスト
- 正常な登録
- パスワード不一致エラー
- ユーザー名重複エラー

**UserAuthenticationTests**: 認証のテスト
- 正常なログイン
- パスワード誤りエラー
- 現在のユーザー情報取得
- 未認証エラー

#### fortune アプリ

**FortuneCalculationTests**: 四柱推命計算のテスト
- 正常な計算
- 未認証エラー
- 無効な日付エラー

**FortuneHistoryTests**: 計算履歴のテスト
- 履歴一覧取得
- 履歴詳細取得
- 履歴削除
- お気に入り切り替え
- 他ユーザーの履歴アクセス拒否

**FortuneCalculationModelTests**: モデルのテスト
- FortuneCalculation作成
- __str__メソッド

### テストデータベース

テスト実行時、Djangoは自動的にテスト用データベースを作成・破棄します。

## フロントエンドテスト（React）

### テストの実行

```bash
# Docker環境
docker-compose exec frontend npm test

# ローカル環境
cd frontend
npm test

# カバレッジ付きで実行
npm test -- --coverage

# CI環境（watch モードなし）
npm test -- --watchAll=false

# 特定のテストファイルのみ実行
npm test -- Loading.test.js
```

### テストライブラリ

- **Jest**: テストランナー
- **React Testing Library**: コンポーネントテスト
- **@testing-library/jest-dom**: カスタムマッチャー

### テストの構成

#### コンポーネントテスト

**Loading Component**
- デフォルトメッセージ表示
- カスタムメッセージ表示
- スピナー表示

**ErrorMessage Component**
- エラーメッセージ表示
- 再試行ボタン表示
- 再試行ボタンのクリック処理

**Header Component**
- アプリタイトル表示
- 未ログイン時のリンク
- ログイン時のリンクとボタン
- ログアウト処理

#### ユーティリティ関数テスト

**dateFormat utilities**
- formatDateTime
- formatDate
- formatBirthDate
- formatRelativeTime

**validation utilities**
- isValidEmail
- validatePassword
- validateBirthDate
- validateHour
- validateUsername

### テストカバレッジ

カバレッジレポートは `frontend/coverage/` に生成されます。

## CI/CDでの自動テスト

### GitHub Actions

プロジェクトでは以下のワークフローが設定されています：

#### 1. Backend Tests (`.github/workflows/backend-test.yml`)

**トリガー**:
- `main`または`develop`ブランチへのpush
- `main`または`develop`ブランチへのPull Request
- `backend/`配下のファイル変更時

**実行内容**:
- PostgreSQLサービスの起動
- Python環境のセットアップ
- 依存パッケージのインストール
- マイグレーション実行
- テスト実行
- カバレッジレポート生成

#### 2. Frontend Tests (`.github/workflows/frontend-test.yml`)

**トリガー**:
- `main`または`develop`ブランチへのpush
- `main`または`develop`ブランチへのPull Request
- `frontend/`配下のファイル変更時

**実行内容**:
- Node.js環境のセットアップ
- 依存パッケージのインストール
- テスト実行（カバレッジ付き）
- ビルドテスト
- アーティファクトのアップロード

#### 3. Docker Build Test (`.github/workflows/docker-build.yml`)

**トリガー**:
- Dockerfileやdocker-compose.ymlの変更時

**実行内容**:
- Dockerイメージのビルドテスト
- docker-compose.ymlの検証

#### 4. Linting (`.github/workflows/lint.yml`)

**トリガー**:
- 全ブランチへのpush/Pull Request

**実行内容**:
- バックエンド: flake8, black, isort
- フロントエンド: ESLint, Prettier

### ワークフローの確認

GitHub リポジトリの「Actions」タブで実行結果を確認できます。

## テスト作成のベストプラクティス

### バックエンド（Django）

1. **テストケースの命名**
   - わかりやすく、何をテストしているか明確に
   - 例: `test_register_user_success`, `test_login_wrong_password`

2. **setUp メソッドの活用**
   - 各テストで共通の初期化処理をまとめる
   - テストユーザーやクライアントの作成

3. **テストの独立性**
   - 各テストは他のテストに依存しない
   - データベースは自動的にリセットされる

4. **認証が必要なエンドポイント**
   ```python
   # トークンを取得
   response = self.client.post('/api/token/', {...})
   token = response.data['access']
   
   # 認証ヘッダーを設定
   self.client.credentials(HTTP_AUTHORIZATION=f'Bearer {token}')
   ```

### フロントエンド（React）

1. **ユーザーの行動をテスト**
   - 実装の詳細ではなく、ユーザーが見る/操作することをテスト
   - `getByRole`, `getByText` などを優先的に使用

2. **非同期処理のテスト**
   ```javascript
   // waitForを使用
   await waitFor(() => {
     expect(screen.getByText('データ')).toBeInTheDocument();
   });
   ```

3. **モックの使用**
   ```javascript
   // API呼び出しをモック
   jest.mock('../services/api');
   
   // 関数をモック
   const mockFunction = jest.fn();
   ```

4. **アクセシビリティ**
   - `getByRole`を使用してアクセシビリティを確保
   - 適切なARIA属性のテスト

## トラブルシューティング

### バックエンド

**問題**: テストデータベースの作成に失敗

```bash
# PostgreSQLに接続権限があるか確認
psql -U postgres -c "CREATE DATABASE test_db;"
```

**問題**: 特定のテストが失敗する

```bash
# 詳細な出力を表示
python manage.py test --verbosity=2
```

### フロントエンド

**問題**: テストがタイムアウトする

```javascript
// jest.config.jsでタイムアウトを延長
module.exports = {
  testTimeout: 10000,  // 10秒
};
```

**問題**: モジュールが見つからない

```bash
# node_modulesを再インストール
rm -rf node_modules package-lock.json
npm install
```
